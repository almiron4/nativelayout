A screen is one text file.

HTML you already know, plus three additions: {value}, if / for lines, and a style with simple selectors. The logic stays in your language, in a screen function.

<!-- tasks.nl -->
<nativelayout>
<link rel="stylesheet" href="tasks.css">

<body>
  <header>
    <img id="back" src="icon:arrow-left">
    <h1>Tasks</h1>
  </header>

  if pending == 0:
    <p>Nothing to do.</p>
  else:
    <p>{pending} pending</p>
  end

  <input id="title" placeholder="New task">
  <button id="add">Add</button>

  for task in tasks:
    <div class="card" key="{task.id}">
      <p>{task.title}</p>
    </div>
  end
</body>
</nativelayout>
// Kotlin: one function holds the state and the taps
fun NativeView.TasksScreen(): Page {
  val s = state { mutableMapOf<String, Any?>("pending" to 2, "tasks" to loadTasks()) }

  if (click("add")) {
    addTask(s, value("title"))
    setValue("title", "")
  }
  if (click(".card")) {
    toggleTask(s, clickIndex())
  }

  return view("tasks.nl", s)
}

The full, runnable version is the tasks example: forms, lists, filters, a progress bar and on-device storage.

Why nativelayout

01

Native output

Buttons, fields, lists and images are real platform views.

02

HTML you know

Tags and CSS-like selectors, with variables through var(--name).

03

Conditions and loops

More than a static canvas: if, elif, else and for, right in the file.

04

Efficient updates

Each render is diffed and only changes are applied. Typed text is kept.

05

Long lists

Give items a key, and mark a container virtual so only the items on screen become views.

06

Header and icons

A fixed header that stays while the screen scrolls, and 30 built-in icons with no image files.

07

Layers and groups

Dialogs and bottom sheets with dialog, grouped fields with fieldset and legend.

08

States and dark theme

Style :pressed, :disabled and :focus, and switch palettes with prefers-color-scheme.

09

Clear errors

Every mistake in a .nl file is reported with its line, in red, on the screen.

Style it like CSS.

Variables, pressed states, gradients, shadows and a dark theme, in a plain .css file linked from the screen.

/* tasks.css */
:root { --bg: #F2F2F2; --card: #EDE9FE; --accent: #2F81F7; }

/* dark theme */
@media (prefers-color-scheme: dark) {
  :root { --bg: #0F172A; --card: #1E293B; }
}

body  { background: var(--bg); padding: 1.25rem; gap: 1rem; }
.card { background: var(--card); border-radius: 0.75rem; padding: 0.875rem;
        box-shadow: 0 2px 4px #0003; }
#add  { background: var(--accent); color: #FFFFFF; font-weight: bold; }
#add:pressed { background: #1F6FE0; }
<!-- a long list: only items on screen become views -->
<div virtual style="gap: 0.5rem">
  for p in products:
    <div class="item" key="{p.id}">
      <p class="name">{p.name}</p>
      <p class="price">{p.price}</p>
    </div>
  end
</div>

One file, any language.

Each language supplies an Expander, an Engine and a native host. The .nl file stays the same.

Install on Android

Published through JitPack. Add both artifacts with the same version. Minimum SDK 21.

// settings.gradle.kts
dependencyResolutionManagement {
  repositories {
    google()
    mavenCentral()
    maven("https://jitpack.io")
  }
}
// app/build.gradle.kts
dependencies {
  implementation("com.github.getnativelayout.nativelayout:nativelayout-android:v0.1.8")
  implementation("com.github.getnativelayout.nativelayout:nativelayout-core:v0.1.8")
}

To try a screen without creating a project, download nativelayout-debug.apk from Releases. It is an editor with code, data, a live preview and a file tree.
